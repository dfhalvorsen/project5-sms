SMS Opt-In Evidence — Project 5 System Alerts

Purpose: This page documents the opt-in mechanism by which the system owner consents to receive SMS operational alerts from the Project 5 market data monitoring system. It is provided so that The Campaign Registry (TCR) and carrier reviewers can verify the consent workflow described in the corresponding A2P 10DLC campaign submission.

Who receives messages

SMS alerts are delivered exclusively to the system owner who deploys and configures the Project 5 software on their own private server. No messages are sent to the general public, customers, or third parties. The recipient and the operator of the system are the same individual.

How consent is collected

The system owner provides explicit, active consent by manually entering their own mobile phone number into the sms_alerts section of the config.yaml configuration file during initial setup of the system. The configuration file contains consent language adjacent to the phone number field that clearly states what the user is agreeing to, message frequency, that message and data rates may apply, and how to opt out.

The phone number field is empty by default. The user must take an affirmative action — typing their number into the file and saving it — for any SMS to be sent. There is no pre-filled value and no default recipient.

config.yaml — opt-in section (verbatim)

The following is the exact content of the sms_alerts section of config.yaml as shipped with the system. The consent language appears as comments directly above the input field:

sms_alerts:
  # ---------------------------------------------------------------------------
  # SMS ALERT CONSENT
  #
  # By entering your mobile phone number below, you consent to receive SMS
  # alerts from this Project 5 system regarding:
  #   - Market data streaming failures (no data received within threshold)
  #   - Process crashes (non-zero exit codes, unhandled exceptions)
  #   - Authentication failures (expired Schwab refresh tokens, etc.)
  #   - Recovery failures (WebSocket reconnect or REST retry exhaustion)
  #
  # Message frequency varies based on system events; typically 0 to 10
  # messages per day.
  #
  # Message and data rates may apply.
  #
  # You may opt out at any time by replying STOP to any alert message.
  # Reply HELP for help.
  #
  # Leaving this field blank disables SMS alerts entirely. No messages will
  # be sent unless a phone number is explicitly entered here.
  # ---------------------------------------------------------------------------
  recipient_phone: ""        # Enter your mobile number in E.164 format, e.g. "+15551234567"
  enabled: false             # Set to true after entering your phone number above
Required disclosures shown to the user at the point of opt-in:
  • Identification of the sender (Project 5 system, operated by the user themselves)
  • Description of the message categories the user will receive
  • Message frequency disclosure (typically 0–10 messages per day, varies)
  • "Message and data rates may apply" disclosure
  • Opt-out instructions (reply STOP)
  • Help instructions (reply HELP)
  • Affirmative action required (field is empty by default; user must enter number AND set enabled: true)

Opt-out mechanism

Every SMS sent by the system includes the text "Reply STOP to opt out." The user may also opt out at any time by:

  • Replying STOP to any message received (handled by the carrier and the messaging provider).
  • Removing their phone number from config.yaml, or setting enabled: false, and restarting the system.

Sample alert messages

All outbound messages identify the system by name and include opt-out language:

  • "Project 5 Alert: No data received for 5 minutes. Check streaming connection. Reply STOP to opt out."
  • "Project 5 Alert: Process exited with non-zero exit code or unhandled exception. Reply STOP to opt out."
  • "Project 5 Alert: WebSocket reconnect or REST retry exhausted all attempts. Reply STOP to opt out."
  • "Project 5 Alert: Schwab refresh token expired; manual browser flow required. Reply STOP to opt out."
